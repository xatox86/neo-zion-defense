# Рейтинг выживания: настройка и проверка

Рейтинг подготовлен отдельно от опубликованной игры. Для работы нужны отдельные Worker и база D1 в аккаунте Cloudflare и токен того Telegram-бота, через которого открывается Mini App. Не размещайте токен в GitHub, клиентском коде, URL, скриншотах или переписке. Приведённые команды развёртывания следует выполнять только после проверки; они изменяют ресурсы Cloudflare.

## Изолированная проверка

1. Установите зависимости проекта и запустите тесты: `npm ci`, затем `npm test` и `npm run typecheck`.
2. Создайте отдельную тестовую базу D1 и отдельный тестовый Worker; не используйте базу будущего публичного рейтинга. В каталоге `workers/leaderboard` выполните `npx wrangler login`, затем `npx wrangler d1 create zion-survival` и подставьте выданный `database_id` в локальную конфигурацию `wrangler.toml`. Имя Worker должно быть уникальным в вашем аккаунте.
3. Примените миграции к **тестовой** базе: `npx wrangler d1 migrations apply zion-survival --remote`. Для локальной базы вместо `--remote` используйте `--local`. Проверяйте выбранный аккаунт и базу до запуска команды.
4. Добавьте токен тестового Telegram-бота через Cloudflare Secrets: `npx wrangler secret put BOT_TOKEN`. Введите значение в интерактивном запросе Wrangler, не добавляя его к самой команде. Команда создания секрета изменяет развёрнутый Worker. Для локального теста можно использовать отдельный тестовый токен в `workers/leaderboard/.dev.vars`; этот файл исключён из Git.
5. В `wrangler.toml` задайте `ALLOW_ORIGIN` — точный origin тестовой игры без пути и завершающего слеша, а также согласованные `SEASON` и `BALANCE_VERSION`. CORS — ограничение браузера, а не проверка личности; сервер отдельно проверяет подпись Telegram.
6. После проверки настройки разверните **тестовый** Worker командой `npx wrangler deploy` из каталога `workers/leaderboard`. Production-сборка по умолчанию использует публичный адрес действующего API из `.env.production`. Чтобы переопределить его для отдельной тестовой сборки, задайте `VITE_LEADERBOARD_API_URL` равной HTTPS-адресу тестового Worker без пути, например в PowerShell `$env:VITE_LEADERBOARD_API_URL = 'https://example.workers.dev'`, затем выполните `npm run build` из корня проекта. Переменная окружения имеет приоритет над `.env.production`. Адрес API является публичной настройкой, не секретом. Не добавляйте секреты в параметры сборки клиента.

Тестовая версия на другом домене имеет отдельное локальное хранилище браузера; её сохранения не переносятся автоматически из опубликованной игры. Убедитесь, что тестовый бот действительно открывает Mini App с непустым `Telegram.WebApp.initData`: обычная вкладка браузера не предоставляет достоверной авторизации Telegram.

Текущий клиент рассчитан на `season-1` и `survival-v1`. При смене сезона или правил игры согласованно обновите эти значения в клиенте и Worker и выпустите новую сборку. Результаты и незавершённые рейтинговые сессии других комбинаций не смешиваются; локальные сохранения сохраняются.

Для локальных браузерных проверок с синтетическими данными запустите отдельный Vite-сервер: в PowerShell из корня проекта задайте `$env:VITE_LEADERBOARD_API_URL = 'https://leaderboard.test'`, затем `npm run dev -- --port 5188`. В другом терминале запустите `node tests/leaderboard-browser.mjs` и `node tests/leaderboard-e2e.mjs`. Второй тест вызывает настоящий обработчик Worker с локальным SQLite-адаптером D1 и тестовой подписью Telegram; он не подключается к аккаунту Cloudflare или реальному боту. Скрипты используют установленный Google Chrome по пути Windows `C:/Program Files/Google/Chrome/Application/chrome.exe`. Для тестирования требуется Node.js с поддержкой `node:sqlite` (в CI используется Node 22).

## Проверка перед выпуском

- Проверить запуск новой рейтинговой игры, последовательное прохождение волн, паузу и восстановление между волнами, завершение поражением и повторную отправку результата.
- Проверить, что `cleared`, а не номер начатой волны, определяет позицию; повторный запрос завершения не создаёт второй результат.
- Проверить два разных аккаунта Telegram, порядок при равном результате, вкладки за всё время, 7 и 30 дней, позицию вне первой сотни.
- Проверить недоступность сети и API, повторное подключение, старое локальное сохранение и смену сезона или версии баланса. Локальная игра должна оставаться доступной.
- Проверить сохранение кампании и управление в Telegram на реальном iPhone; отладочная эмуляция браузера не заменяет эту проверку.

## Ограничения защиты

Подпись `initData` подтверждает аккаунт Telegram, но не доказывает, что игра на устройстве не изменена. Сервер проверяет состояние сессии, порядок волн, повторные запросы и базовые временные ограничения, однако модифицированный клиент может имитировать правдоподобные события. Для соревновательной защиты в будущей версии нужна серверная симуляция боя или проверяемый журнал действий с воспроизводимым на сервере расчётом и сверкой контрольных состояний. До этого результаты следует считать предварительными, а не защищёнными от мотивированного мошенника.

Workers и D1 можно использовать на бесплатном плане в пределах квот. При превышении лимитов API может перестать отвечать до их сброса; проверьте актуальные лимиты и настройте мониторинг в аккаунте. См. официальные инструкции [Cloudflare D1](https://developers.cloudflare.com/d1/get-started/), [миграции Wrangler](https://developers.cloudflare.com/d1/wrangler-commands/), [секреты Workers](https://developers.cloudflare.com/workers/configuration/secrets/), [лимиты D1](https://developers.cloudflare.com/d1/platform/limits/) и [проверку данных Telegram Mini Apps](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).
