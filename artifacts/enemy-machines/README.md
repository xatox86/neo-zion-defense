# Enemy Machines 2.0 — development review

The seven concept sheets in `concepts/` are original generated designs informed by the supplied references. The game uses generated transparent turnaround and component atlases, packed by `tools/prepare_enemy_atlases.py`. Four illustrated views and their mirrored counterparts are selected in eight angular sectors; these are not eight independently modelled 3D views. Independently overlaid components provide the motion, but the underlying body images still contain some integral appendages. These limitations require an art and animation pass before this can be considered a complete replacement for fully rigged 3D or directional animation.

Boss visual stages use remaining HP thresholds of two thirds and one third. Existing combat phase, jammer effect, carrier reinforcement and economy are unchanged. Boss death delays the main explosion until after initial mechanical effects. A seeded wave-10 mobile browser episode and visual image-difference tests are reproducible with the `tests/enemy-machines-*.mjs` scripts; the episode is not a normal full campaign playthrough. The FPS sample is desktop Chrome with an emulated 390×844 mobile viewport, not a physical phone; measured heap is a browser snapshot, not total GPU or device memory.

Outstanding: direction transitions and articulated limb attachment need visual refinement on each route, fully independent hull/limb artwork and distinct authored destruction sequences are still needed for every class, and mobile Safari / actual device performance and complete balance playthrough have not been verified.
