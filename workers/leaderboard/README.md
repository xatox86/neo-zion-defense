# Worker API

Инструкции настройки D1, секретов и клиента находятся в [LEADERBOARD_SETUP.md](../../LEADERBOARD_SETUP.md).

Все запросы, кроме CORS OPTIONS, требуют `Authorization: tma <Telegram.WebApp.initData>`. Сервер проверяет подпись и время `auth_date`; после 24 часов Mini App необходимо вновь открыть через Telegram, чтобы получить новые данные. Никакой идентификатор из тела запроса не считается удостоверением личности. Имя игрока берётся из проверенных данных Telegram и возвращается как обычный текст; отображайте его через `textContent`.

API:

- `POST /v1/sessions` с `{ "season": "season-1", "balanceVersion": "survival-v1", "requestId": "UUID-v4" }` начинает рейтинговую сессию; клиент создаёт и сохраняет `requestId` до отправки. Повтор с тем же UUID для того же подтверждённого игрока идемпотентно возвращает исходную сессию даже после потери ответа; для другого игрока это отдельная сессия. При смене версии или сезона старый `requestId` вернуть в рейтинг нельзя. Ответ содержит `sessionId`, `requestId`, `season`, `balanceVersion`, `cleared`, `status` и `reached`.
- `GET /v1/sessions/:sessionId` восстанавливает состояние собственной сессии. Пауза не ограничена по времени; после смены сезона или версии баланса сессия несовместима и не может быть продолжена в рейтинге.
- `POST /v1/sessions/:sessionId/waves` с `{ "wave": 1 }` подтверждает одну полностью отражённую волну. Волны принимаются последовательно. Повтор последней подтверждённой волны идемпотентен. До волны N должно пройти не менее N секунд с момента создания сессии; накопленную офлайн очередь можно отправить по порядку после восстановления связи. Сервер принимает до 5000 волн в одной рейтинговой сессии; локальное выживание этим лимитом не ограничено.
- `POST /v1/sessions/:sessionId/finish` с `{ "cleared": 1, "reached": 2 }` фиксирует поражение; `reached` всегда равен `cleared + 1`. Повтор того же результата идемпотентен. Одной сессии соответствует одна запись результата.
- `GET /v1/leaderboard?period=all|week|month` возвращает `season`, `balanceVersion`, `entries` (до 100 позиций) и `me` (позиция текущего игрока даже за пределами первой сотни либо `null`). Неделя и месяц означают скользящие последние 7 и 30 суток. Учитывается лучший результат каждого игрока за выбранный период; сортировка идёт по `cleared`, затем по времени достижения и идентификатору для стабильного порядка.

Ответы содержат `Cache-Control: no-store`. Ошибки возвращают `{ "error": "код" }`: `401` означает отсутствие или истечение Telegram-аутентификации, `409` — несовместимость версии либо нарушение последовательности, `429` — ограничение частоты. Без конфигурации серверного секрета и D1 API возвращает `503`.

Проверка Telegram доказывает идентичность владельца Telegram-сессии, но браузер сообщает о волнах сам. Игрок с модифицированным клиентом может сфальсифицировать ход боя: данный API не является надёжным античитом. В будущем для соревновательного рейтинга потребуется авторитетная симуляция боя на сервере либо проверяемая запись действий и воспроизведение с серверной фиксацией версии, случайного зерна, состояния и временных ограничений.
